# H-SETS — Computer skills before Lesson 1

[Course contents](README.md)

An operating system, such as Windows or Linux, manages the computer's hardware and provides services for programs. An application helps you perform a task, such as writing a document. A process is a running instance of a program. Closing an application differs from shutting down the computer.

The processor carries out instructions. RAM holds working data while programs run; ordinary RAM loses its contents when power is removed. Storage holds saved files and installed software. Save a document to a known location and reopen it to check that the saved contents are present. A larger storage drive does not provide additional RAM.

A file stores named information. A folder organises files, and a path describes a location. Two files can have identical names in different folders. Copying creates another copy; moving changes a location. A filename extension suggests a format, but changing the extension does not convert the file or prove that it is safe.

Use invented information for this practice:

1. Create an H-SETS practice folder with Original and Copy folders inside it.
2. Write a short attendance note in a text editor and save it as attendance.txt in Original.
3. Close the editor, locate the file and reopen it. Confirm the contents.
4. Copy it into Copy, add a sentence to the second file and save it.
5. Open each file from its own folder and explain why their contents differ.
6. Record both paths and take a screenshot that contains no personal data or passwords.

You are ready to begin when you can find the files, explain which one changed and distinguish the application from the saved document. Two folders on one drive are useful for practice, but do not protect against failure of that drive.

An account represents an identity in a system. Permissions determine which actions it may perform. An access refusal may be intentional; do not grant administrator rights merely to remove an error. Record the action, location and error and ask for help when the next step is outside the assigned task.

## Check your practical readiness

Before Week 4, demonstrate these actions using harmless practice files. Ask for a demonstration, repeat it independently, then record the result.

- Open the course homepage in a browser, enter a module, follow a lesson link and return using the navigation links. Keep the lesson and instructions in separate tabs.
- Download the repository ZIP using GitHub's Code menu, extract it to a known folder and open a Markdown file in a text editor. Do not edit the only copy of your course notes.
- Display filename extensions, distinguish a text file from an executable, and identify the complete path to your saved work.
- Copy a harmless example such as `pwd` into the assigned terminal, identify which machine the terminal controls and explain the command before pressing Enter. Do not paste unfamiliar administrator commands.
- Find available disk space and explain how it differs from installed RAM and total drive capacity.
- Record an exact error, the action that produced it, the machine involved and a screenshot without secrets.

Before network labs, explain these ideas: a client requests a service from a server; an IP address identifies a network destination; a port identifies a transport endpoint; DNS resolves names; a gateway routes traffic to other networks. Draw a browser contacting a web server and label the client, server, name, address and port. A failed website request alone does not identify which part failed. Use the networking lesson for the fuller explanation.

For each check record **independent**, **needed help**, or **not yet**. Repeat the items needing help before the related live activity. These checks support readiness; they do not add a new course grade.
